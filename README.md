# Legacy Order Modernization

Пример постепенной модернизации небольшого приложения на чистом PHP: учёт заказов
(создание, позиции, расчёт суммы со скидкой, статусы, отмена).

В репозитории две версии одного приложения:

- `legacy/` — исходная процедурная версия. **Она написана специально для этого проекта**, чтобы показать
  процесс модернизации, и не взята из реального коммерческого кода. Типичные для старых проектов проблемы
  в ней есть (смешение HTML, SQL и логики, дублирование, глобальное состояние, отсутствие валидации и тестов),
  а намеренных уязвимостей вроде SQL-инъекций — нет.
- `src/`, `templates/`, `public/` — модернизированная версия с теми же URL, полями форм и разметкой.

Подробный разбор каждого шага и всех изменений поведения — в [docs/MODERNIZATION.md](docs/MODERNIZATION.md).

## Стек

- PHP 8.4+, PDO, Composer (PSR-4). Без фреймворков и без runtime-зависимостей.
- MariaDB 11.8 / MySQL — основная БД; SQLite — для тестов и быстрого локального запуска.
- PHPUnit 12, PHPStan (level 8).
- Docker Compose, GitHub Actions.

## Возможности

- Список заказов с фильтром по статусу и суммой каждого заказа.
- Создание заказа, добавление позиций, расчёт суммы: скидка 5% от 10 000 руб.
- Статусы `new → paid → shipped`, отмена из `new` и `paid`; пустой заказ нельзя оплатить.
- Защита форм от CSRF, валидация с сообщениями у формы, понятные страницы 404/409/503.

## Структура

```
legacy/                 исходная версия (не меняется, нужна для сравнения и тестов)
public/                 точки входа модернизированной версии: orders.php, order.php
bootstrap.php           сборка объектов, обработка ошибок, подключение к БД
src/
  Database.php          создание PDO с безопасными настройками
  Order/
    Order.php           заказ: позиции, сумма, скидка, смена статуса
    OrderItem.php       позиция и проверка ввода
    OrderStatus.php     статусы, названия, допустимые переходы
    Money.php           разбор и форматирование сумм в копейках
    OrderRepository.php весь SQL
    OrderService.php    изменения заказа: создание, позиции, статусы
    *Exception.php      ошибки валидации (422), состояния (409), «не найден» (404)
  Http/
    OrderController.php обработка запросов страниц заказов
    View.php, Response.php, Csrf.php
templates/              HTML-шаблоны
database/               schema.sql (MySQL), schema.sqlite.sql, seed.sql,
                        migrations/ — переход существующей legacy-базы
bin/                    создание SQLite-базы, выполнение SQL-файла для тестовой БД
tests/
  Unit/                 правила заказа, статусы, деньги
  Integration/          репозиторий и сервис на реальной БД
  Http/                 контроллер без веб-сервера (входит в набор Integration)
  Characterization/     legacy и новая версия через HTTP с одинаковыми действиями
docs/MODERNIZATION.md   ход модернизации
```

## Запуск через Docker

```bash
docker compose run --rm app composer install
docker compose up -d
```

- Новая версия: http://localhost:8080/orders.php
- Исходная версия: http://localhost:8081/orders.php

Обе работают с одной базой MariaDB, как при постепенном переходе. Схема и демо-данные загружаются
при первом запуске контейнера `db` из `database/schema.sql` и `database/seed.sql`.
Чтобы пересоздать базу: `docker compose down -v && docker compose up -d`.

## Запуск без Docker (SQLite)

Нужен PHP 8.4+ с `pdo_sqlite`. Команды для Linux/macOS:

```bash
composer install
php bin/create-sqlite-db.php var/orders.sqlite
DB_DSN="sqlite:$PWD/var/orders.sqlite" php -S 127.0.0.1:8080 -t public
```

В PowerShell (Windows): `$env:DB_DSN="sqlite:$PWD\var\orders.sqlite"; php -S 127.0.0.1:8080 -t public`.

Путь к файлу нужен абсолютный: встроенный сервер PHP делает текущей папкой `public/`,
и относительный путь указывал бы на `public/var/orders.sqlite`.

## Настройки окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `DB_DSN` | `mysql:host=127.0.0.1;dbname=orders;charset=utf8mb4` | строка подключения PDO |
| `DB_USER`, `DB_PASSWORD` | пусто | учётные данные БД |
| `TEST_DB_DSN`, `TEST_DB_USER`, `TEST_DB_PASSWORD` | `sqlite::memory:` | БД для интеграционных тестов |

Пароль `secret` в `compose.yaml` — только для локального контейнера.

## Схема БД

Инструмента миграций нет: схема применяется SQL-файлами.

Новая база:

```bash
mysql -u orders -p orders < database/schema.sql
mysql -u orders -p orders < database/seed.sql   # демо-данные, все вымышленные
```

Существующая база legacy-версии: сначала выполнить запросы-проверки из
`database/migrations/001_add_foreign_key_and_status_index.sql` (позиции без заказа, неизвестные статусы,
отрицательные цены), затем сам файл. Он добавляет внешний ключ `order_items → orders` и индекс по статусу,
колонки не меняет — legacy-страницы продолжают работать.

## Пример использования

Приложение — HTML-страницы с формами, не API. Пример запроса curl к новой версии
(сначала нужно получить CSRF-токен и cookie сессии со страницы):

```bash
curl -c cookies.txt -s http://localhost:8080/orders.php | grep -o 'name="csrf_token" value="[^"]*"'
curl -b cookies.txt -i -X POST 'http://localhost:8080/order.php?id=1' \
  -d csrf_token=<токен> -d action=add_item -d product_name=Ручка -d quantity=3 -d price=45,50
# HTTP/1.1 303 See Other
# Location: order.php?id=1&msg=item_added
```

## Тесты и проверки

```bash
vendor/bin/phpunit                          # все тесты (SQLite)
vendor/bin/phpunit --testsuite Unit         # только модульные, без БД
vendor/bin/phpstan analyse                  # статический анализ
```

Интеграционные тесты на MariaDB (в пустую тестовую базу):

```bash
export TEST_DB_DSN='mysql:host=127.0.0.1;dbname=orders_test;charset=utf8mb4' TEST_DB_USER=orders TEST_DB_PASSWORD=secret
php bin/run-sql.php database/schema.sql
vendor/bin/phpunit --testsuite Integration
```

GitHub Actions: тесты на PHP 8.4 и 8.5 (SQLite), интеграционные тесты на MariaDB 11.8 и проверка Docker Compose —
обе версии должны показать одинаковую сумму демо-заказа.

## Ключевые решения

- **Те же URL и формы.** Модернизация не заставляет пользователей переучиваться и позволяет держать
  обе версии рядом. Поэтому вместо роутера — два тонких файла в `public/`.
- **Без фреймворка.** Задача проекта — показать, как навести порядок в коде без смены платформы.
  Маршрутизация, DI и шаблонизатор здесь укладываются в несколько десятков строк.
- **Тесты на совпадение с legacy.** Прежде чем менять логику, нужно зафиксировать текущее поведение;
  намеренные отличия тоже закреплены тестами.
- **Целые копейки** вместо `float` для денег.
- **Защита от устаревшей страницы.** Формы смены статуса передают статус, который видел менеджер; если заказ
  с тех пор изменился, действие отклоняется. Запись условная (`WHERE status = ?`), без блокировок — одинаково
  работает в MariaDB и SQLite.
- **Минимум классов.** Нет интерфейсов с одной реализацией, базовых классов и контейнера.

## Известные ограничения

- Нет аутентификации (как и в legacy) — только для внутренней сети.
- Пока legacy-версия работает с той же базой, она может записать неизвестный статус. Новая версия покажет такой
  заказ, но менять его не даст — данные нужно исправить вручную.
- Нет пагинации списка, удаления позиций, редактирования заказа.
- Схема описана в двух файлах (MySQL и SQLite), их нужно менять вместе.
- Характеризационные тесты используют SQLite; на MariaDB проверяются интеграционные тесты и Docker-сценарий в CI.
- Docker-окружение — для разработки (встроенный сервер PHP), не для эксплуатации.
